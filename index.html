Counterflow: Distributed Spatio-Temporal Dynamic Pricing & Causal Policy Platform

Causal Inference • Offline Reinforcement Learning • Uber H3 Hexagonal Simulator
GitHub Repo →

The Problem: Why Naive Machine Learning Fails in Dynamic Pricing

In production marketplaces (like ride-sharing, food delivery, and streaming CDN routing), price surges occur when unobserved latent demand spikes (such as heavy rainstorms, stadium concerts, or peak hours) happen.

Because high demand and high prices coincide in historical logs, standard supervised machine learning models mistakenly learn that high prices cause higher demand. When deployed, naive models aggressively overprice users, causing catastrophic churn. Furthermore, live exploration burns customer goodwill, while naive offline Q-learning overestimates unvisited actions.

The Solution: Counterflow Three-Pillar Architecture

  • Robinson Double Machine Learning (DML): Deconstructs the problem in two stages by predicting demand from confounders and surge prices from confounders separately, subtracting out the nuisance components to isolate the true exogenous causal price sensitivity curve without bias.
  • Conservative Q-Learning (CQL): Penalizes out-of-distribution pricing actions in historical trajectory logs, guaranteeing a strict lower bound on true policy value.
  • Doubly Robust Off-Policy Evaluation (DR-OPE): Combines inverse propensity weighting and outcome reward models to produce unbiased 95% bootstrap confidence bounds before live rollout.
Plain-Text Technical Architecture Summary

Robinson DML: Uses K-fold cross-fitting to isolate the treatment effect. Residualized conversion is regressed on residualized surge prices, achieving mathematical consistency even when nuisance models converge at slower non-parametric rates.

Distributed Serving: Shipped with a sub-2ms asynchronous FastAPI dispatch service, Ray distributed worker pools for batch trajectory evaluation, and a Redis spatial cache partitioned over Uber H3 hexagons.

Interp Circuit Engine: Sparse Autoencoders & Causal Steering

Mechanistic Interpretability • Sparse Autoencoders • Activation Steering in PyTorch
GitHub Repo →
Top-K Sparse Autoencoder architecture. High-dimensional polysemantic residual activations are intercepted via forward hooks and decomposed into 3,584 monosemantic latent concept features. Causal activation steering injects scaled concept directions back into the forward pass.

Decomposing Polysemantic Neurons into Monosemantic Concepts

In frontier Large Language Models, single neurons are polysemantic: one neuron fires for a chaotic mixture of concepts (like French verbs, legal dates, and python syntax).

Interp Circuit Engine resolves this superposition dilemma by training overcomplete Top-K Sparse Autoencoders (SAEs) that project dense 896-dimension residual vectors into 3,584 distinct, monosemantic latent features. Enforcing exact top-32 feature activations per token eliminates the severe feature shrinkage bias seen in standard L1 autoencoders.

Causal Activation Steering & Direct Logit Attribution

  • Direct Logit Attribution (DLA): Projects decoder feature vectors directly onto the model's unembedding vocabulary matrix, instantly discovering which words each latent feature boosts or suppresses.
  • Causal Activation Injection: Modifies intermediate transformer layer activations in real time during the forward pass, steering text generation toward targeted semantic domains without prompt engineering.
  • Streaming Ring Buffer: In-memory token-shuffling ring buffer decouples intra-document correlation during extraction hooks, supporting Apple Silicon (MPS), CUDA, and CPU.

Open-World Continual Learning for Autonomous Agents

Autonomous Vehicle Perception • Elastic Weight Consolidation (EWC) • Waymo to nuScenes
GitHub Repo →
Cross-domain autonomous perception pipeline. Adapting YOLOv11m from Waymo Open Dataset (Phoenix/SF) to nuScenes (Boston/Singapore) using Elastic Weight Consolidation (EWC) and Entropy-based Open-Set Recognition.

Preventing Catastrophic Forgetting Across Cities

Perception detectors trained on one geographic domain (like Waymo in sunny Phoenix) suffer severe performance loss when transferred to new domains with different weather, sensor rigs, and vehicle styles (like nuScenes in rainy Boston and Singapore).

We integrated Elastic Weight Consolidation (EWC) into a YOLOv11m backbone. EWC measures the Fisher Information matrix to calculate which weights are vital to prior driving environments, penalizing parameter updates that would destroy prior knowledge while learning new classes.

Real-Time Open-Set Recognition (OSR)

  • Entropy Uncertainty Thresholding: Analyzes predictive entropy on detection heads to flag never-before-seen obstacles (construction debris, rare vehicles) as Unknown/Out-of-Distribution instead of misclassifying them with false confidence.
  • High-Speed Production Inference: Containerized with Docker Compose and FastAPI, achieving sub-120ms CPU inference latency suitable for edge perception.
  • MLOps Pipeline: End-to-end experiment tracking with MLflow and reproducible dataset versioning via DVC.

LLM Fine-Tuning for Mathematical Reasoning (STaR)

Llama-3.2-3B-Instruct • Self-Taught Reasoner Bootstrapping • GSM8K Benchmark
GitHub Repo →
Empirical STaR mathematical reasoning research dashboard: live GSM8K multi-step reasoning trace inspection, automated verification, Vanilla SFT vs STaR loss curves, accuracy progression (44.0% SFT vs 58.4% STaR), and 4-bit LoRA adapter rank matrix weight heatmap.

Why Vanilla SFT Failed vs. Rationale Bootstrapping

In our initial experiments on GSM8K using Llama-3.2-3B-Instruct, vanilla supervised fine-tuning achieved only 44.00% accuracy, underperforming even Zero-Shot Chain-of-Thought (47.56%). Direct supervised training caused the model to overfit on superficial formatting rather than learning general problem-solving logic.

The STaR Verification & Rationalization Loop

  • Rationale Bootstrapping: Prompts the model to generate step-by-step reasoning chains. If the answer is verified correct, the chain is retained.
  • Rationalization of Mistakes: If incorrect, the ground-truth answer is provided to prompt the model to discover a working derivation, repairing flawed steps.
  • 4-Bit QLoRA Acceleration: Quantized to 4-bit precision via bitsandbytes and bfloat16 adapters, slashing GPU memory consumption by 75% for single-GPU training.
